# 通用诊断对象与适配器

## 入口模型

> v0.3 更新：面向测试的入口已改为自然语言问题 + 已知环境信息，自动核对对象和选择流程；下述显式对象请求作为内部及兼容接口保留。见[自动诊断入口与调度架构](自动诊断入口与调度架构.md)。

工单不应绑定某个中间件编号。用户选择环境与登记对象，并描述现象，例如“test-a 的订单 Java 服务接口超时”。统一请求：

```json
{
  "environment_id": "test-a",
  "target_type": "java_service",
  "target_id": "orders-api",
  "symptom": "升级后接口间歇性超时，发生于北京时间 14:00–14:20"
}
```

`target_id` 是环境内稳定、由管理员登记的资源别名，不是任意命令、地址或路径。具体容器 ID、主机连接、服务名、挂载点或 YARN 应用编号由对应适配器解析。不要将同一别名重新指向无关资源；后续需增加资源身份/版本基线以核验运行期间的变化。

## 类型与能力边界

| target_type | 诊断对象示例 | 后续可接入的只读能力 | 当前真实适配器 |
| --- | --- | --- | --- |
| docker_container | 容器或容器组 | 状态、退出码、限量日志、资源指标 | 未实现，仅演示 |
| virtual_machine | 虚拟机/宿主机 | CPU、内存、进程、系统日志 | 未实现，仅演示 |
| java_service | Java 服务 | 健康、日志、GC、受控线程采样 | 未实现，仅演示 |
| go_service | Go 服务 | 健康、日志、受控 pprof | 未实现，仅演示 |
| network | 登记的网络链路/端点 | DNS、TCP、TLS、延迟 | 未实现，仅演示 |
| storage | 磁盘、挂载点、存储服务 | 容量、inode、挂载与 I/O 指标 | 未实现，仅演示 |
| yarn_application | Flink/Spark 等 YARN 应用 | 应用状态 | 已实现 REST 适配，待公司环境验收 |

类型表示业务对象，adapter 表示采集实现，两者不能混为一谈。例如 Java 服务可能运行在 Docker 或虚机上，后续通过资源关系关联它们；本次没有实现依赖拓扑或跨资源自动归因。不能把“登记了类型”理解为“已能诊断该类型的全部问题”。

## 注册与执行

新注册格式：environment → targets → target_id → {target_type, adapter, label, ...类型专用配置}。仅管理员配置文件可指定连接信息。当前仅接受 demo 和 yarn 适配器；不能把 docker、ssh 等未实现名称写入配置期待自动执行。

执行器通过认证的对象目录接口公开环境、对象 ID、类型、名称及 demo/yarn 来源，不公开地址、连接信息和凭据。API 代理目录并验证新工单的目标组合，执行器再次验证目标和工具权限。通用调用为 get_target_status，YARN 专用旧工具仅可用于 YARN 对象。

证据、报告、Worker 领取与结果校验使用同一工单/环境/对象类型/对象 ID 作用域。新类型的演示结果只声明尚未采集真实状态，不虚构 CPU、磁盘、端口或服务故障。

## 下一阶段

先根据用户现场可用的访问方式选择一个真实适配器验证，例如登记 Java/Go 健康接口，或用受控主机代理提供 Docker 状态与日志。接入 SSH、Docker Socket、JMX 或 pprof 前需确认实际认证和影响范围；这些凭据与采样权限不因对象类型被选择而自动获得。
